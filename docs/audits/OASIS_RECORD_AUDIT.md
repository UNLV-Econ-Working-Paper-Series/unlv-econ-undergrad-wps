# OAsis Record Audit

Audit date: 2026-08-31 (America/Los_Angeles)

Scope: all 15 current frontend records and their public OAsis item pages in the [Undergraduate Economics Working Paper Series](https://oasis.library.unlv.edu/econ_ug_papers/).

Result: **no title, author-order, abstract, keyword, DOI, canonical URL, repository-online date, citable date, volume, issue-number, or page-range mismatch was found.** The exact public OAsis rights label, `In Copyright`, was added to each local record. No faculty sponsor, issue-publication date, disclosure, license, or private evidence was inferred.

The repeatable external run is preserved as [JSON](./oasis-external-verification.json) and [Markdown](./OASIS_EXTERNAL_VERIFICATION.md). The run retrieved all 15 item pages and resolved every DOI to the expected OAsis item. Automated PDF range requests produced a mix of HTTP 206 and HTTP 403 responses, and individual results varied across bounded reruns. The generated snapshot is the authoritative transport observation; neither response is treated as a metadata mismatch or an accessibility determination.

## Method and authority

Each live OAsis item page was compared with its corresponding file in `src/content/papers/`. The comparison covered the public HTML metadata, visible item fields, DOI redirect target, canonical item URL, and canonical PDF URL. OAsis is treated as canonical for repository title and author metadata, DOI, item URL, repository-online date, and repository-hosted PDF.

OAsis exposes both a citable `Publication Date` and a separate `bepress_citation_online_date`. The audit preserves these meanings:

- `citable_published_at` is the OAsis citation date;
- `repository_published_at` is the date the item became available online in OAsis;
- `issue_published_at` remains absent because neither a semester nor a volume/issue pair proves an issue-release date.

The local controlled research field and semester-style issue term are editorial metadata. OAsis exposes related disciplines plus volume and issue, but not those local fields. They are therefore recorded below as non-comparable rather than represented as repository-verified.

## Citation comparison

The frontend default citation and the OAsis repository citation were checked record by record. They use the same author order, title, citable year, volume, issue, pages, and DOI. Expected presentation differences remain:

- OAsis abbreviates given names and labels the DOI as “Available at.”
- The frontend retains fuller public author names and includes the immutable `series_number`.
- The frontend canonicalizes the DOI to `https://doi.org/`; the OAsis display currently uses `http://dx.doi.org/`.

These are citation-format differences, not record mismatches. Consumers should still follow the current style guide required by their instructor, journal, or publisher.

## Rights and public/private boundary

Every audited item page visibly states `IN COPYRIGHT` and links to RightsStatements.org. The public local value is deliberately limited to the corresponding label `In Copyright`. It does not create a reuse license, identify a copyright holder, or prove permission to redistribute.

No private consent evidence, signed agreement, review, ballot, correspondence, or internal rights evidence was added to the public schema or records. Schema tests reject uncontrolled private evidence fields.

## File-accessibility limits

The item records identify the files as English-language PDFs. The external verifier made only a bounded HTTP range request. A 200/206 response, selectable text, successful text extraction, or browser rendering would still be insufficient to establish accessibility.

No complete audit of document title, language metadata, tags, headings, reading order, bookmarks, tables, figures, alternative text, links, equations, contrast, or page numbering was performed. The unresolved accessibility owner is Series operations under the published accessibility-request process.

## Re-running the external check

Run manually or at release time from the repository root:

```bash
npx tsx scripts/verify-oasis-records.ts
```

Optional bounded controls are `--timeout-ms` (1,000–60,000), `--attempts` (1–5), and `--concurrency` (1–6). Output is always written before the command reports a nonzero exit status: exit 1 means a metadata/DOI-target or local-data failure; exit 2 means only network or remote HTTP failures were observed.
